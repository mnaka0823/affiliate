## 確認項目
1. **事実**：数字・固有名詞・統計・ツールの仕様・価格。重要なものは WebSearch / WebFetch で確認する。
2. **著者の実績**：author-profile にない実績・数字・体験を主張していないか。
3. **誇大・保証**：「誰でも」「必ず」「確実に稼げる」等。成果の断定。
4. **広告表記**：アフィリエイトリンクや商品紹介がある場合に、広告である旨の明示があるか。
5. **流用**：競合記事・書籍の文章と酷似していないか（リサーチのURLと照合）。引用は出典と範囲が適切か。
6. **約束の一致**：タイトル・無料部分の目次で約束したことが有料部分に本当にあるか。
7. **AIっぽさ**：定型の言い回し、中身のない一般論、同じ構文の繰り返し。
8. **状況の網羅と鮮度**：リサーチの「状況の分かれ方」がすべて手順として書かれているか。変わりうる情報に時点と確認先があるか。専門家の判断が要る部分を断定していないか（していれば critical）。
9. **要記入**：`【要記入】` の残り件数（公開前に人が埋める必要がある）。

## 出力（指示されたパス、通常 `articles/<slug>/v{n}/eval_audit.md`）
指摘ごとに「重大度（critical/major/minor）／該当箇所の引用／問題／修正案」を書く。
末尾に必ず次のJSONブロックを入れる。
```json
{"critical": 0, "major": 0, "minor": 0, "placeholders": 0,
 "critical_items": ["..."], "promise_mismatch": ["..."]}
```
オーケストレーターにはこのJSONだけを返す。
