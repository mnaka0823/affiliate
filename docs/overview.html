アーキテクチャ

全体を動かすのは、メインセッションで動くオーケストレーターです。各工程はサブエージェントが担当し、受け渡しはすべてファイルで行います。青い線が、評価の結果を受けて直す工程へ戻る流れです。

受け渡しはファイル

各工程が articles/<日付>-<slug>/ に結果を書き、次の工程が読みます。何がどこで変わったかを後から追えます。

評価は読者と同じ条件

評価役には、構成の意図や改訂メモを見せません。ペルソナは先に感想を書き、そのあと基準の文に照らして点をつけます。

投稿は人が行う

公開、基準の変更、実績の記録は人が判断します。著者プロフィールにない実績は作らず、「要記入」として残します。

テーマの選び方

最初のテーマ選びは「繰り返し検索されるか」で行い、500〜980円を払う理由の確認が抜けていました。いまは払う理由を最初の関門にしています（方針 v2）。

関門A　最重要

払う理由がある

損得
価格の10倍以上の価値に見える
切迫性
期限・事件・不安で、今知りたい
成果物
文例・チェックリストなど、そのまま使える
代替
無料の公式情報やAIとの差を1文で言える
関門B

読まれる

需要
検索やSNSで探されていて、時期にピークがある
財布
買い手が自分でお金を出す層である
関門C

書ける・安全に出せる

資格
税務・法律の個別助言にならない
正確
公的な一次情報で裏づけ、確認日を書く
著者
自分の経験で語れる

優先度 = 損得×3 + 代替されにくさ×3 + 切迫性×2 + 成果物×2 + 需要×2 + 財布 + 著者 + 加点4項目

どれかの関門が2点以下なら候補から外します。加点は、状況で分かれる、繰り返し陥る、古くなりにくい、情報がまとまっていない、の4つです。

緊急対処型個人情報が流出したら、詐欺の振込をした直後
予防チェックリスト型流出前にやる設定、年末調整の書類カレンダー
お金が戻る手続き型住宅ローン控除、ふるさと納税、医療費控除
時短ツール集型職種を絞った業務AIプロンプト

ループが止まる条件

設定は config/pipeline.json で変えられます。終了したときは、最後の版ではなく、最も点の高かった版を採用します。

終わり方条件
合格平均の購入意向が 4.0 以上、満足度が 4.0 以上、懐疑派の購入意向が 3.0 以上、品質監査の致命的な指摘が 0 件
上限改善は最大 3 回まで
頭打ち総合点の伸びが 0.15 未満の状態が 2 回続いたとき

無料やAIとの差

全テーマで3点止まりでした。差が出るかは、文例・順番・確認表の作り込み次第です。

数字の原典

流出事案の件数、控除額の上限、期限は報道や民間サイトが根拠です。国税庁などは未接続です。

通しの動作

8つのエージェントを続けて動かした実績がありません。1本目で不具合が出る可能性があります。

noteの規約
