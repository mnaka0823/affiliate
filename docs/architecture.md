# 設計ドキュメント：note有料記事 量産マルチエージェント

## 1. 当初案と最終構成

| # | 当初案 | 最終構成（エージェント名） | 変更点 |
|---|---|---|---|
| 0 | オーケストレーター | `/note-article` スキル（メインセッション） | Claude Code の**サブエージェントは別のサブエージェントを起動できない**ため、オーケストレーターはサブエージェントではなくメインセッションで動くスキルにした |
| 1 | 企画・ネタ調査 | `trend-researcher` | 「需要（検索・SNS）」「競合の有料記事」「価格相場」「過去の自分の販売実績」の4軸で調べ、候補を**スコア付きで複数**出す |
| 2 | ペルソナ作成 | `persona-builder` | 1人ではなく**3〜5人**。「買う人」に加えて**「迷って買わない人（懐疑派）」を必ず1人**入れる。デモグラだけでなく予算・悩み・過去に買って失敗した経験まで書く |
| 3 | 構成設計 | `structure-architect` | note特有の**有料ライン（どこで切るか）と価格**を構成と同時に決める |
| 4 | 文章作成 | `article-writer` | 構成とペルソナに忠実に書く。改訂時は前版との差分方針を受け取って直す |
| 5 | タイトル選定 | `title-optimizer` | 20案以上を生成 → 機械的に足切り → ペルソナ視点の**一対比較トーナメント**で1つに絞る |
| 6 | ペルソナ評価 | `persona-evaluator`（ペルソナ数だけ並列）＋ **`quality-auditor`（新規）** | 評価を「無料部分→買うか」と「有料部分→払った価値があったか」の**2段階**に分けた。事実確認・規約・誇大表現は別エージェントで見る |
| 7 | 3,4,5を回す | `improvement-director` ＋ オーケストレーターのループ | 7は「回す係」ではなく、評価から**原因を診断して、3/4/5のどれを直すかと具体的な修正指示を出す係**にした。実際に回すのはオーケストレーター |
| — | （なし） | `/note-learn` スキル | 公開後の**実際の販売数**を記録し、次回の調査・評価に反映する。ペルソナ評価はあくまで代理指標なので、本物の結果で補正する |

## 2. 全体フロー

```
/note-article [テーマ or 空]
 │
 ├─ ① trend-researcher ……… ネタ候補（空なら複数）→ 1つ選び深掘り      → 01_research.md
 ├─ ② persona-builder ……… 3〜5人（懐疑派1人を含む）                  → 02_personas.md
 │
 │  ┌──────────── 改善ループ（最大 N 回、最良版を保持）────────────┐
 ├─ ③ structure-architect … 構成＋有料ライン＋価格                     → v{n}/outline.md
 ├─ ④ article-writer ……… 本文                                       → v{n}/draft.md
 ├─ ⑤ title-optimizer …… 20案→足切り→一対比較                         → v{n}/titles.md
 ├─ ⑥ persona-evaluator ×人数（並列） ＋ quality-auditor（並列）       → v{n}/eval_*.md
 ├─ ⑦ improvement-director … 集計・診断・継続/終了判定・修正指示        → v{n}/director.md
 │     └ 継続なら「直す工程」だけを v{n+1} で再実行（③から/④から/⑤だけ）
 │  └──────────────────────────────────────────────────────┘
 │
 └─ 仕上げ：最良版を note 貼り付け用 final.md に整形 ＋ 公開前チェックリスト
           （公開は人が行う）

公開後： /note-learn → knowledge/performance.csv と learnings.md を更新 → 次回の①②⑥が参照
```

## 3. 設計の根拠（調査結果）

### 3.1 エージェント構成のパターン
- Anthropic「Building Effective Agents」は、まず単純な構成から始め、効果が測れたときだけ複雑にすることを勧めている。
  今回の構成は、固定順の **Prompt chaining（①→⑤）**、評価と改善を繰り返す **Evaluator-optimizer（⑥⑦のループ）**、
  ペルソナ評価の **Parallelization（並列評価＝投票）** の組み合わせ。
  Evaluator-optimizer は「評価基準が明確で、反復で測れるほど良くなる」ときに向くとされるため、
  評価基準（`knowledge/evaluation-rubric.md`）を明文化した。
- Claude Code のサブエージェントはそれぞれ独立したコンテキストで動き、ツールを個別に絞れる。
  一方で**サブエージェントからサブエージェントは起動できない**ので、ループ制御はメインセッション側に置く必要がある。
- 実例では、エージェント同士の受け渡し（ハンドオフ）を**ファイル経由**にし、
  各段階に品質ゲートを置く構成が報告されている。本構成もすべて `articles/<slug>/` 配下のファイルで受け渡す。

### 3.2 ペルソナ評価の信頼性
- LLMに「1〜5で点数をつけて」と直接聞くと精度が低く、**自由記述で反応を書かせてから尺度に対応づける**方が
  人間の購買意向調査に近づく（約90%の再現性）という研究がある（arXiv 2510.08338）。
  → `persona-evaluator` は**先に率直な感想を書き、その後で定義済みの基準文（アンカー）に照らして点をつける**手順にした。
- 同研究では、ペルソナの属性情報を抜くと評価が一様に甘くなった。
  → ペルソナには予算・懐疑点・過去の失敗購入まで書かせ、懐疑派を必ず入れる。
- 同研究自体も、LLMパネルは**人間調査の前の一次ふるい**と位置づけている。
  → 最終的な正解は実売データとし、`/note-learn` で補正する。
- 自分が書いた文章を自分で評価すると甘くなりやすいので、評価エージェントには
  執筆側の意図メモを渡さず、**読者と同じ情報（タイトル・無料部分・有料部分）だけ**を渡す。
  また点数の絶対値より、**前版との一対比較**を重視する。

### 3.3 noteで売れる有料記事の傾向
- note社が約30万件の有料記事・メンバーシップを分析した結果として、売上の伸びが大きいジャンルは
  「テクノロジー・AI活用」「SNS・コンテンツ運用」「副業・在宅ワーク」と報じられている。
- 単発の有料記事は 500〜3,000円に集中しているという解説がある（実売データの公開は限られる）。
- 売れない原因は文章よりも**価格と有料ラインの位置**にあることが多い、という実践者の分析がある。
  → 価格と有料ラインは構成段階で決め、ペルソナ評価でも「この価格なら買うか」を聞く。
- いきなり有料記事を出すより、無料記事で信頼を作ってから有料化する方がよいという意見も多い。
  → `trend-researcher` は関連する無料記事の案も出す。

## 4. 記事の方向性
テーマ選びの基準は `knowledge/theme-direction.md` に分けて置き、全工程が参照する。
狙いは「繰り返し検索される、手順が決まった悩み」。6条件（答えが決まっている／古くなりにくい／情報が散らばっている／
状況で分かれる／経験で書ける／繰り返し起きる）で採点し、単価より検索の繰り返し（C3・C6）を重く見る。
各工程への反映：
- ①リサーチ：6条件で採点し、7項目（検索キーワード・場面・状況の分かれ方・無料/有料の中身・次に困ること）を出す。`/note-themes` で一覧表にできる
- ②ペルソナ：状況パターンA/B/Cと、悩みに陥る頻度を散らして割り当てる
- ③構成：状況分岐型（無料で判定チャート、有料でパターン別手順・テンプレ・見返し用チェックリスト）
- ⑥評価：「状況への適合」「見返しやすさ」を診断項目に追加。監査では状況の網羅と情報の時点を確認
- 仕上げ：「次に困りそうなこと」を `next-themes.md` に残し、`/note-batch --series` でシリーズ化

## 5. 停止条件（暴走防止）
`config/pipeline.json` で調整する。
- 合格：全ペルソナ平均の購入意向 ≥ 4.0、満足度 ≥ 4.0、懐疑派の購入意向 ≥ 3.0、`quality-auditor` の致命的指摘 0件
- 上限：最大3回の改善ループ
- 頭打ち：総合点の伸びが 0.15 未満の状態が2回続いたら終了
- 終了時は**最後の版ではなく最高得点の版**を採用する

## 6. 限界と注意
- ペルソナ評価は実際の売上を保証しない。数本公開して実売との相関を見るまでは、点数は目安として扱う。
- note の利用規約・ガイドライン（AI生成物、情報商材、誇大表現など）は変わりうるので、公開前に公式ページを確認する。
- アフィリエイトリンクを入れる場合は、ステルスマーケティング規制（景品表示法、2023年10月施行）に沿って広告であることを明示する。
- 公開（投稿）は自動化せず、人が最終確認してから行う。
